# Return packet: S2-crew (Wave 2, lane 2), 2026-10-31

## SLICE

The crew gains two seats and five protections. All of it is deterministic and offline. There is no live call, no send and no prompt-byte change.

- **CP1 (i): replay is bound to a manifest.** Each recorded turn now carries the sha256 of the manifest of the case it was recorded for. The manifest covers: artifact path and bytes, ask, call-contract digests, the L-1 prompt pins, model id, roster version `a2+s2-2026-10-31`, and the S2 block plus its evidence files on S2 cases. `runCase` recomputes the digest from the case it actually runs and the bytes it actually read. A stale stamp throws. A turn recorded under a different manifest is refused at the model seam. All 20 A2 cases and their turns are stamped by `scripts-ts/stamp-case-digests.mts`, which is idempotent and has a `--check` mode. The 20 A2 trajectories replay byte-identically against a full-record gold dumped before any lib edit.
- **CP1 (ii): one request per turn on the live crew path.** `maxRetries: 0` is set, and `CrewLiveUsage.attempts` is counted at the transport. A test drives the real `ai` and `@ai-sdk/groq` over an offline transport stub and sees exactly one request per turn; with `maxRetries` removed it sees three.
- **CP2: routing is a deterministic table** (`lib/crew/route.ts`, labelled "deterministic workflow"). Ownership is supplied by the case, never inferred. Human-escalation dominates every row when the Reviewer escalates or an anomaly is on record; an exhaustive property test over 3,240 inputs proves it. The Reviewer sees the computed route. A Reviewer turn that sees one renders **"requalification pending"**; a legacy turn keeps "agent (live-run floors cleared)".
- **CP3: two new registry tools.** `explain_drift` is the deterministic baseline; evidence validity and abstention are gating. Results on engine-computed findings: agent-86 → merchant-edit, sync-outage → sync-latency, platform-override → platform-override, and partner-onboarding → **unknown**. The partner-onboarding result is derived, not assumed: its drifted rows are last touched by integrator `price_edit`/`86` events and by actor-`unknown` overrides, and no rule row names either pair. With the event log stripped, every scenario returns unknown. A field named like a class, at any nesting level, is refused, and the error names the field. `size_impact` wraps lib/impact (now the real merged module). Both tools are registered and described; MCP still advertises the original seven (see OPEN).
- **CP4: the roster gains `root-cause` and `impact`.**
  - **Root-cause:** the orchestrator calls `explain_drift` under contract, and the LLM root-cause seat renders DEFER.
  - **Impact:** `size_impact` is called only when the case names an orders file; otherwise a typed SKIPPED step records "no orders data in this case".
  - **Route:** the route is computed, then the Reviewer turn runs with `computedRoute`. An unowned route sends an approved run to the human gate.
  - **Live lane:** `SOR_CATALOG_PATH` is now a parameter defaulting to the old constant, and the surface can be chosen by the case (security finding F9). The examined `CREW_LIVE_TOOL_NAMES` is untouched; `CREW_LIVE_TOOL_NAMES_S2` is separate.
  - **Render:** shows the route, the explanation with cited events, DEFER, impact with the chip `[simulated]`, and the Reviewer state with the F3a truth.
  - **Cases:** 9 new replay-only cases in `evals/crew/cases-s2/` (5 root-cause, 4 impact), pinned by the new `crew-composition-lock-s2.test.ts`, which re-derives every expectation and both new contracts from the engine.
- **Amendment 2: budget on the live crew path.** Each turn is reserved, makes one request, and is settled against the S2-ledger API. Unknown usage is charged at the reservation. An overflow halts the ledger, and the next turn is refused before any request. The default live path refuses to run without a ledger.
- **Amendment 3: ledger hand-off.** `toLedgerEntryInput` is pure; a type-check plus an in-memory `appendLine`/`verify` prove its output is a lib/ledger `LedgerEntryInput`. Nothing is written to any file.
- **Security review items:**
  - F2: tool reads are limited to `fixtures/`, `evals/` and the OS temp dir, with dot-segments refused. The MCP server returns fixed error text, with no echo of the path, file bytes or absolute paths.
  - F5: a shared 5 MB cap is checked before any read.
  - F8: the crew reads case artifacts through the same path guard.
  - F3c and amendment 4: a per-run crypto nonce goes on both quarantine markers, and bracket pairs and their look-alikes inside the excerpt are neutralized.
  - F3b and amendment 4: the scan folds NFKC, invisible characters and confusables in two views (stripped and spaced), with five obfuscated fixtures.
  - F3a: the truth is stated in the render text (below).

## DEVIATIONS (each with reason)

1. **New S2 cases live in `evals/crew/cases-s2/`, not `evals/crew/cases/`.** The pre-registered A2 lock asserts exactly 20 ids in `cases/`, and the replay-floors golden freezes a 20-row matrix. The same reason applies to `harness-s2.ts` being a new file: `harness.ts` is unchanged.
2. **The manifest adds `askSha256`** (plus an `s2` block on S2 cases only). The packet's own test names "change its ask", and the ask is model input. Legacy digests depend on A2 fields only.
3. **`IntakeTurnInput.manifestDigest` is optional, and lookup only checks it when the input supplies one.** The untouchable A2 lock probes turn existence without a digest. `runCase` always supplies one (tested by a spy), and RecordedModel refuses an unstamped fixture entry at construction. `CrewCase.manifestDigest` is optional because `cases-live/**` (the L-1 split, frozen) is not stamped.
4. **explain_drift interpretive rule.** A merchant edit on a row the engine reports EXPIRED (LST-STALE-EXPIRED) reads as sync-latency, and needs a sync marker on record (none means unknown). Without this, sync-outage's merchant-edited rows conflict with its stale rows. Event targets also have a convention: scope-level targets such as `catalog` or a category name are sync markers, not row touches, and an item id touches its `-vN` variations. Any (actor, action) pair outside the table reads unknown, including integrator `price_edit`/`86`. The run-level class is given only when every finding agrees.
5. **The two tools' schemas and implementations are inline in `registry.ts`.** `lib/tools/schemas/**` and `lib/tools/tools/**` are outside the lane.
6. **MCP keeps advertising seven tools** (an explicit allowlist), and `tools/call` refuses the two unadvertised names. Advertising them needs `evals/mcp/**` edits and a transcript re-record (see OPEN).
7. **Two impact-mapping refinements per the S2-impact packet.** `category` is mapped as `?? ""`, so the `size_impact` schema admits an empty category. The orders path is exercised by one pinned case over a 6-order fixture in `evals/crew/fixtures/`, not over the 144 KB main fixture, which would have been embedded in the case contract.
8. **Orchestrator amendments widened the file scope to `lib/tools/paths.ts`.** Budget, ledger and security items were added as checkpoints.
9. **`toLedgerEntryInput` declares the ledger shape structurally.** The crew's import walk (untouchable) bars `lib/crew` from importing `lib/ledger`; the test proves the shape is equal.
10. **The test environment never makes a live call.** One test in `crew-live-fetchers` stubs `ENABLE_LIVE_AI=true` and a placeholder `GROQ_API_KEY` via `vi.stubEnv`, restored by `afterEach` → `vi.unstubAllEnvs()`. It does this to prove the default live path refuses before any request when no ledger is passed; the throw precedes `generate`, so no request can be reached. The transport-stub tests load the real `ai` and `@ai-sdk/groq` with the string `offline-stub-not-a-key`, against an in-process `Response` stub. No socket is ever opened, and the process `ENABLE_LIVE_AI` is never set.
11. **`maxRetries` and attempts reporting.** With no injected transport, attempts is reported as 1, which follows from `maxRetries: 0`; it is counted only when a transport is injected. Wrapping the global fetch would add a `fetch(` call to `lib/agents`.
