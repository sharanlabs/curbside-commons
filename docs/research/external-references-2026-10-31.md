## Top 5 for the S3 packet (official preferred; corroboration noted)
1. **DoorDash envelope + category + item.** `store{merchant_supplied_id, provider_type}`; `menus[]{id, reference, open_hours[{day_index "MON", start_time, end_time}], special_hours[{date, closed, start_time, end_time}], menu{name, subtitle, merchant_supplied_id, active, categories[]}}`; category `{name, subtitle, merchant_supplied_id, active, sort_id, items[]}`; item `{name, description, merchant_supplied_id, active, is_alcohol, is_bike_friendly, sort_id, price, base_price, tax_rate, extras[]}` (sample response; `base_price` from dual-pricing/FAQ). Field is `active`, not `is_active`. Max lengths: name 500, description 1000, merchant_supplied_id 1024; ids unique within a menu level. Consumer-side `storepageFeed` shape is a different surface — never mix.
2. **DoorDash extras + options + price semantics + override rule.** extra `{name, description, merchant_supplied_id, active, sort_id, min_num_options, max_num_options, num_free_options, min/max_option_choice_quantity, min/max_aggregate_options_quantity, options[]}`; option `{name, description, merchant_supplied_id, active, price, base_price, default, sort_id, tax_rate, extras[]}`. `price` = Delivery, `base_price` = Pickup/Storefront/Voice. Tax rate whole number (5, not .05). Omit a field, never null. Scenario 4 encodes Override vs Sticky. **Price unit: integers paired to "$12.99" in prose — label "cents inferred", never state as fact.**
3. **Uber envelope + item.** Top level `menus / categories / items / modifier_groups` all required. Menu `{id, title, service_availability[{day_of_week "monday", time_periods[{start_time "07:00", end_time}]}], category_ids}`. Titles are `{translations: {en_us}}`. Item `{id, title, description, price_info{price, in_store_price, in_store_discounted_price}, tax_info{tax_rate}, modifier_group_ids{ids[]}, quantity_info, suspension_info, external_data}`. Price = integer in lowest denomination (verified verbatim). Corroboration: storefront `catalogItems{uuid, title, price, hasCustomizations}` (two sources).
4. **Uber modifier groups + 86.** Group `{id, title, modifier_options[{type "ITEM", id}], quantity_info{quantity{min_permitted, max_permitted}}, display_type}` — modifiers are references to items, structurally unlike DoorDash's nested options (good for round-trip goldens). 86 = `suspension_info.suspension.suspend_until` Unix seconds; item-level updates via POST …/menus/items/{item_id}. Corroboration: storefront `customizationsList{minPermitted, maxPermitted}`.
5. **Order Errors CSV + id-mapping.** Uber's own guidance is the design rule: parse by header name, ignore unknown columns, expect country variation and new columns. Content to simulate (prose-only, both platforms): issue type · item(s) in error · customer refund · merchant charge · amount the platform covers; categories missing / incorrect item / incorrect order; windows Uber > 96 h not covered, DoorDash ≥ 72 h absorbed, 14-day dispute. **Column names are OURS, labeled "shaped like the described contents".** Id-mapping: DoorDash `merchant_supplied_id` vs Uber item `id` / `external_data` are opaque merchant-controlled strings — the mapping sheet is genuinely needed. Partner scorecard inputs: DoorDash certification demos (menu pull, deactivate/reactivate, failed-POST message), 48 h SLA on visible menu issues, < 1 % failure/cancel; Uber 99 % injection-success floor and "don't clear a menu before PUT".

## Horizon (off-radar, for the plan)
- **UCP PR #897 is a direct conformance hook for scenarios 6 and 8:** "every line_items[].dish MUST come from that establishment's active menu"; menus and prices in discovery "are provisional" and re-validated against live kitchen state; platforms "MUST echo authoritative title and price"; `note` "MUST NOT alter price". Business-authored price is the line we already audit. #821 (nested options, depth ≤ 5) and #824 (selection rules) are draft versions of our modifier model.
- **menuconform** (Apache-2.0, Ruby, 0★) is an adjacent "can an agent build a valid cart from this menu" checker — not a threat to the platform-side, evidence-grade, human-gated position, but plan copy must not claim nobody does agent-cart conformance.
- Google's Food Ordering AI Agent Menu API is a published non-UCP food menu model with modifier-group constraints — a useful third vocabulary.
- DoorDash is pull-based (`MENU_PULL`), Uber is push-with-overwrite (PUT): the adapters treat both as document shapes, but scenario 3 (sync outage) behaves differently under each.
