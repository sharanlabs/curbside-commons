## The two P1s — both real, both mine, both the session's own failure class

### P1-1 — the scorer certified a 19-case run as complete

`scripts-ts/l1-consistency-score.mts` derived its universe of cases from **the union of ids seen in
the matrices**. A case degraded in *one* rep was caught. A case absent from *every* rep never entered
that union at all — so it was not "dropped", it did not exist: `droppedIds` came back empty,
`completeCoverage` came back `true`, and the run certified as `FLOORS CLEARED` at C-5 **19/19**.

Reproduced locally by removing `l1-int-injection-visible` — an **injection-resistance** case — from
all three reps: `allPass = true`.

This is exactly the denominator-shrinking the file's own header promised to prevent. The guard failed
because **it asked the data what should be there.** The general rule now recorded: *a completeness
check must take its denominator from the specification, never from the observations.*

**Fix.** Authoritative ids now come from the 20 committed case files; ids outside the split and
duplicate ids are hard refusals; the coverage rules were extracted into `resolveCoverage()` in the
already-tested module so they are testable at all, and pinned by 6 tests. **Red-green proven** by
restoring the union-of-observed logic: exactly one test fails — `THE REGRESSION: a case absent from
EVERY rep is still counted as missing` — and only that one.

### P1-2 — a comment asserted a containment the code never implemented

My own comment on `L1_OUT_DIR` read *"resolved against the gold dir, so it cannot escape it."*
`join()` performs no containment. Verified empirically:

| `L1_OUT_DIR` | resolved to |
| --- | --- |
| `..` | `evals/crew` — **escaped** |
| `.` | `evals/crew/gold` — **the canonical K=1 record** |
| `../../..` | the repo root |

`L1_OUT_DIR=.` would have pointed the destructive probe-write straight at the artifacts this
parameter exists to protect. **A comment claiming a guarantee the code does not implement is worse
than no comment: it stops the next reader from checking.** That is the identical shape as the
`$0`/zero-network claim (session 34) and the `vercel.json` "correct shape" claim (earlier this
session) — a claim broader than its backing, committed by me *while fixing that very class*.

**Fix.** Strict `consistency/rep-<N>` grammar + symlink-aware resolution + containment check +
refusal when the target already exists (a rep that overwrites a previous rep is not an independent
pass). All five attack vectors verified to refuse.
