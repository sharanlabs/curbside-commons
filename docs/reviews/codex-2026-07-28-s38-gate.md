### [P3] F-3 · the fold guard's run-control check asserted nothing about the fold
**File:** `evals/e2e/canonical.spec.ts:104`
**Finding ACCEPTED · proposed FIX REFUTED on a measurement.**

`toBeVisible()` in Playwright means "has a box and is not hidden" — it says
nothing about the viewport. Paired with the comment *"the run control is on the
page without hunting for it"*, it read as a fold guarantee it never made.

The gate proposed `toBeInViewport({ ratio: 1 })` for both zones **and** the
button. Measured at 1280×900 before writing anything:

```
ZONE The feed:   y=657.5  height=214.2  bottom=871.7
ZONE The record: y=657.5  height=214.2  bottom=871.7
RUN BUTTON:      y=970.5  height=50.4   bottom=1020.9
```

**The button sits below the fold by design** — it follows both drop zones. The
proposed fix would fail against the current design and is refuted.

**Fix, split to match what is actually true:**
- **Zones strengthened.** `y < 900` (starts above the fold) → `y + height <= 900`
  (sits *entirely* above it). The original was weaker than the requirement it
  named — a zone beginning at 880 passes it while being almost wholly below the
  fold. The stricter reading holds today with ~28px of headroom.
- **Button comment corrected to the truth**, and the real invariant pinned: the
  button must follow the record zone within 200px (measured gap 98.8px, 2×
  headroom) — *the next thing after the zones*, not buried further down.
